1. Analysis & Design

Before creating a database, you must plan it. This involves identifying the data requirements and how tables link together.

Entities & Attributes

  • Entity: The thing we store information about (e.g., a Student, a Car, a Movie). This becomes the Table name.
  • Attribute: The specific details of the entity (e.g., Name, Age, Cost). These become the Fields/Columns.

Keys & Relationships

Relational databases split data into multiple tables to reduce data duplication (redundancy).

  • Primary Key (PK): A field that uniquely identifies every record in a table (e.g., DriverID). It cannot be left blank (Null).
  • Foreign Key (FK): A field in one table that links to the Primary Key of another table.
  • Relationship: National 5 focuses on One-to-Many relationships.
    Example: One Teacher has Many Pupils.

The Data Dictionary

A design document describing the database structure.

FilmID Integer - PK Unique

Validation Types

  • Presence Check: Ensures the field is not left empty.
  • Range Check: Ensures numbers are within limits (e.g., Age 0-120).
  • Restricted Choice: User selects from a specific list (e.g., Small, Medium, Large).
  • Length Check: Ensures text has a specific number of characters (e.g., Password must be 8+ chars).

2. Searching with SQL (SELECT)

The SELECT command is used to retrieve data from the database. It never changes the data, only views it.

The 4 Keywords of Search

SELECT field1, field2
FROM TableName
WHERE criteria
ORDER BY field ASC;

Example 1: Simple Search

Find the names of all 'Action' movies.

SELECT title, director
FROM Cinema
WHERE genre = 'Action';

Example 2: Complex Criteria (AND / OR)

Find movies that are 'Comedy' AND have a rating higher than 8.

SELECT title, rating
FROM Cinema
WHERE genre = 'Comedy' AND score > 8;

Note: Text uses single quotes ('text'). Numbers do not.

Example 3: Sorting (ORDER BY)

Find all customers and sort them alphabetically by Surname (A-Z), then by Age (Oldest to Youngest).

SELECT firstname, surname, age
FROM Customer
ORDER BY surname ASC, age DESC;
  • ASC: Ascending (A-Z, 0-9)
  • DESC: Descending (Z-A, 9-0)

Example 4: Equi-Join (Two Tables)

Sometimes you need data from two linked tables. You must match the keys in the WHERE clause.

SELECT Player.name, Team.team_name
FROM Player, Team
WHERE Player.team_id = Team.ID
AND Team.city = 'Glasgow';

3. Modifying Data with SQL

These commands change the actual data in the database.

INSERT INTO (Adding a new record)

Adds a new row to a table.

INSERT INTO Customer (name, town, points)
VALUES ('John Smith', 'Dundee', 50);

UPDATE (Editing existing records)

Changes data in a row. Warning: Always use a WHERE clause or you might update every row in the table!

UPDATE Customer
SET points = 100, town = 'Edinburgh'
WHERE customerID = 45;

DELETE (Removing records)

Removes a row permanently.

DELETE FROM Customer
WHERE customerID = 45;
